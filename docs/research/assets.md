# Asset shortlist — Poly Haven (CC0) for *Pıtır'ın Kristal Adası*

Generated 2026-11-08 from `https://api.polyhaven.com/assets` + `https://api.polyhaven.com/files/<id>` (metadata only — nothing downloaded yet). All assets are CC0 (credit Poly Haven + author in `assets/CREDITS.md` anyway).

## Key findings (read first)

1. **Poly Haven glTFs have a single LOD.** The `.bin` is shared by the 1k/2k/4k/8k variants and holds the full-resolution mesh; only the JPG textures change with resolution. Triangle counts below were read from the glTF accessors (exact). The catalog `polycount` is the Blender file's and is often far higher for plants (e.g. `celandine_01`: 1.7M in blend vs 9k in glTF).
2. **Realistic trees are not mobile-feasible as-is**: `island_tree_01/02/03` = 46–85 MB (1.1–1.6M tris in glTF for 01/02), `jacaranda_tree` 215 MB, `pine_tree_01` 958 MB. Only `quiver_tree_02` (4.55 MB, 82k tris) fits. Keep the procedural trees, dress them with Poly Haven bark textures (`palm_bark`, `bark_brown_02`, `pine_bark`), and if a hero tree is wanted, download `island_tree_02` once at build time and run `gltf-transform simplify --ratio 0.02` + texture resize offline (never ship the source).
3. **Ground cover is nearly free**: `moss_01` 204 tris, `grass_bermuda_01` 941, `fern_02` 6k, `grass_medium_02` 7.8k, `celandine_01` 9k, `shrub_sorrel_01` 3.3k — all 0.8–1.5 MB at 1k. Rocks: `moon_rock_*` 3–19k tris at ~1.5 MB each, `rock_face_01/02` are 20–30k-tri proxy cliff sections (7 m / 5 m). `rock_moss_set_01/02` give 6 mossy rocks each for 1.9 MB.
4. **Missing on Poly Haven (CC0)**: lava, ice, palm trees, cactus, clouds. Plan: lava = procedural emissive noise shader; ice = procedural MeshPhysicalMaterial (no transmission on mobile) or `marble_cliff_01` (white rock); palms = procedural trunk with `palm_bark`; clouds stay sprites.
5. **Texture budget**: every texture here has diff + nor_gl + arm at 1k JPG, 1.0–3.8 MB per set (median ≈ 2.3 MB). Shrinking to 512 px for the mobile tier roughly quarters that. Two bark textures were dropped for size at 1k: `jolcham_oak_bark_01` (6.5 MB), `palm_tree_bark` (5.1 MB).
6. **HDRIs**: all `*_puresky` ids are 3–6 MB at 2k, 0.7–1.9 MB at 1k (use 1k on mobile). `rosendal_plains_2_puresky` and `venice_dawn` do **not** exist (404 → dropped); `rosendal_plains_2`, `venice_dawn_1/2`, `venice_sunset` do.
7. **glTF extensions seen** (three.js r186 GLTFLoader handles all): `KHR_materials_specular`/`ior` (several plants, statues), `KHR_materials_transmission` (`Lantern_01`, `lantern_chandelier_01` — transmission is expensive on mobile, swap the glass material), `KHR_materials_emissive_strength` (`ocean_buoy`), `KHR_texture_transform` (`island_tree_02`).

### How sizes were measured / how to download later

- Model row = `gltf.1k` entry of `files/<id>`: total = gltf JSON + `.bin` + all `include` textures (1k JPG). Verdict rules: **REJECT** total > 6 MB; **heavy** bin > 3 MB or > 100k tris; **ok-decimate** 50–100k tris (run `gltf-transform simplify`); **ok** otherwise. Size column is Poly Haven's bounding box in metres (x × y × height, z-up in Blender).
- The glTF references `<id>.bin` and `textures/<id>_<map>_1k.jpg` *relatively*; the `include` map of the API gives the exact URL for each relative path. The bin URL is **not** under `/gltf/1k/` — it lives under `/gltf/4k/` or `/gltf/8k/` depending on the asset — so a downloader must read `include` (or the manifest at the end of this file), never guess.
- Texture rows: 1k JPG, URL pattern verified for every id: `https://dl.polyhaven.org/file/ph-assets/Textures/jpg/1k/<id>/<id>_{diff|nor_gl|arm}_1k.jpg` (`Rough`, `AO`, `Displacement` also exist; `arm` = AO/Rough/Metal packed, matching the current `index.html` material setup).
- HDRI rows: `https://dl.polyhaven.org/file/ph-assets/HDRIs/hdr/2k/<id>_2k.hdr` (verified); replace `2k` with `1k` for the mobile tier (sizes given).
- Every glTF peeked was generated by *Khronos glTF Blender I/O*: one `.gltf` JSON + one external `.bin` + relative JPG textures, no Draco/meshopt compression, no LOD nodes (mesh names like `*_PROXY_5m` / `realCap_Model_*` are the scan or proxy mesh, not LOD levels).
- Attribution: CC0, but Poly Haven asks for a credit; the `authors` field is included in the manifest for `CREDITS.md`.

## Pipeline notes for the download step

1. Fetch `https://api.polyhaven.com/files/<id>` with a browser-like `User-Agent` (Python's default UA gets HTTP 403; curl works).
2. For models, save `gltf.1k.gltf.url` as `<id>_1k.gltf` and every `include` entry at its relative key (`<id>.bin`, `textures/<id>_diff_1k.jpg`, …) next to it.
3. Optimise before shipping: `npx @gltf-transform/cli optimize in.gltf out.glb --compress meshopt --texture-compress webp --texture-size 512` (mobile) / `1024` (desktop); add `simplify --ratio` for the *ok-decimate* rows. Split multi-mesh sets (`rock_moss_set_*`, `namaqualand_rocks_01`, `moon_rock_01`) into separate nodes so the level API can place them individually.
4. Alpha-card plants (grass, flowers, fern, moss) need `material.alphaTest ≈ 0.5`, `side = DoubleSide`, and should be instanced (`InstancedMesh`) per level.
5. `arm` textures: R = AO, G = roughness, B = metalness — same convention as the existing `index.html` materials.
